# 계산중이쥐 · Calculatemouse v3.0

**GitHub Pages에 올릴 `site.zip`**입니다. 기존 `Unzip and Deploy PWA` 액션을 수정할 필요가 없도록 `zone1` 엔진과 UI를 `app.js`에 통합했습니다. ZIP 내부에는 사이트 파일이 최상위에 있습니다.

## 실제 앱 화면 변경
- 홈 중앙 상단에 큰 **보라/금색 햄스터+계산기 문장**(`assets/main-emblem.svg`) 표시. 같은 문장을 PWA 설치 아이콘(`icon-192.png`, `icon-512.png`)으로 사용.
- 기존의 보라·금색 배경, 유리 느낌 버튼, 흩날리는 햄스터 파티클 유지.
- 사용자가 제공한 두 컷 이미지에서 햄스터를 분리하여 `assets/*-hamster.png`의 작은 스티커로 삽입.
- 모바일은 하단 탭, 홈 카드 버튼으로 화면 이동.

## 길드원 관리
- 최초 길드원은 **0명**. 1~4군 및 미지정을 선택하여 추가하거나 기존 길드원의 군을 바꿀 수 있습니다.
- 전체 / 1 / 2 / 3 / 4 / 미지정 필터 지원.
- 기존 보스 격추 보너스 및 지역 격추 보너스는 보존.
- 군 필드는 백업 JSON에 포함. 1구역 기여도·보상도 같은 JSON 백업에 포함.

## 계산 메뉴
- **상층 1구역**: 격전쥐, 유령 꿀벌, 유령 꽃게, 유령 토끼. 몬스터의 최대 체력(HP)과 길드원별 퍼센트 기여도 입력.
- **상층 2구역**: 기존 상층 보스 계산기를 그대로 이관.
- **일격 점수**: 기존 별도 계산을 유지.

### 1구역 기여율 입력 방식
- `게임에 표시된 최종 %`: 입력한 기여도 퍼센트를 그대로 사용합니다. 이미 적용된 보너스/손실을 중복 적용하지 않습니다. **기본 선택입니다.**
- `보정 전 기본 %`: 개인 기본 격추와 서버 격추 보너스, 2배속 점수 손실률(기존 계산기 값 **4.29%**) 및 입력한 격추 횟수당 손실률을 적용합니다.
- 격추 1회당 손실률은 실제 값이 확인되지 않아 **기본 0%**, 사용자가 직접 입력해야 합니다.
- 길드원이 아닌 참가자 또는 미입력 기여도 때문에 합계가 **100% 미만이어도 정상**입니다. 합계가 100%를 넘으면 경고하고 추첨을 중단합니다.
- 개별 기여율/격추 횟수/보상 기록은 현재 **기기별 로컬 저장**입니다. 향후 공용 동기화 시 길드원 군 분류는 서버 공유 대상이지만, 기여율·보상은 별도 공유 규칙이 필요합니다.

### 보상 2단계 분배 (초기 규칙)
1. 길드가 **실제로 획득한 보상 종류·수량·개당 가치(상대값)**를 직접 입력합니다. 게임 아이템 목록/실제 가치는 아직 제공받지 않았으므로 기본값을 만들지 않았습니다.
2. 획득 보상 **개수**를 군별 **1군 30%, 2군 25%, 3군 25%, 4군 20%**로 최대 잔여법을 사용하여 정수 배정합니다. 총 수량이 적을 때 각 군에 정확히 같은 퍼센트를 배정할 수는 없습니다.
3. 실제 아이템 각각을 1차 배정량만큼 군에 무작위 할당합니다. 군 안에서는 길드원 최종 기여율을 가중치로 2차 추첨합니다. 보상 가치가 클수록 고기여도 가중치가 커지고, 기존 획득 가치가 높은 사람의 가중치는 일부 줄어듭니다.
4. 보상은 추첨 결과에 따라 지급 대상으로 표시합니다. **길드원 없음·기여도 0인 군의 배정 보상은 지급 보류**하며 다른 군으로 임의 이전하지 않습니다.
5. 기본 공식은 **현재 합의된 앱용 가설 규칙**입니다. 실제 게임의 공식 보상 계산법 및 아이템 가치를 검증한 결과는 아닙니다. 관리자가 보상을 실제 지급하기 전에 확인해야 합니다.

## 공용 서버
- 코드 `server/Code.gs`의 길드원 데이터에 `group`(0~4)을 추가했습니다. 서버 신규 생성은 `setupServer()` 실행 후 등록하면 됩니다.
- **기존 시트가 이미 있다면 `migrateRosterGroupColumn()`을 한 번 실행**해 10번째 `group` 열을 생성하세요. 기존 길드원 이름/격추/프로필 버전을 수정하지 않습니다.
- 실제 Apps Script / Cloudflare Worker는 **아직 배포되지 않았습니다**. 연결되기 전에는 기기 내부에만 저장됩니다.
- 공용 연결 구성과 계정 키는 절대 공개 GitHub 파일에 넣지 마세요.

## GitHub 업로드
1. 저장소 `Calculatemouse` 최상위의 `site.zip` 파일을 새로 생성하거나 교체해 커밋합니다.
2. 설치해둔 `.github/workflows/unzip-deploy.yml` 액션이 실행돼야 합니다. `Settings → Pages → Source`는 `GitHub Actions`로 설정합니다.
3. 배포 주소: `https://gamingtaehawn4321-lab.github.io/Calculatemouse/` (배포 완료 후 접근 가능).
4. 이전 홈 화면이 캐시되어 있다면 인터넷 연결 후 새로고침합니다. 새 서비스 워커 캐시 버전은 `gyesanjungiji-pwa-v4-groups-zone1-hero`입니다.

## v3.2 전역 배경음악
- 제공받은 `rat beat.mp3`를 `assets/rat-beat.mp3`로 포함했습니다 (약 81.8초). 전체 화면에서 같은 `<audio>`를 공유하므로 탭을 바꿔도 끊기지 않습니다.
- `loop` 자동 반복, 음악 켜기/끄기, 볼륨 슬라이더, 선택한 설정의 기기별 저장을 지원합니다.
- 브라우저가 자동재생을 막을 경우 첫 화면 터치나 음악 버튼 클릭으로 시작합니다. PWA에서도 브라우저의 재생 정책을 따릅니다.
- iPhone/iPad Safari는 웹페이지의 볼륨 값을 무시할 수 있으므로 기기 볼륨 버튼을 이용해야 할 수 있습니다.
- `sw.js` 캐시를 v7로 갱신하고 음악 파일을 오프라인 캐시 목록에 넣었습니다. 배포 액션은 `assets` 폴더를 그대로 복사해야 합니다.
